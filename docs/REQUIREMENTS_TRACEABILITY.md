## How To Use The Matrix

For each active implementation issue, identify the concrete test or review artifact
and its path before setting `Ready`. Replace generic area-wide `Test Target` and
`Thesis Evidence` descriptions with issue-specific artifact names as the work is
sliced into pull requests. Keep the issue, approved requirement revision and
evidence version connected when scope changes.

Use the existing scenario, benchmark and release issues for these refinements.
This matrix does not introduce additional product scope or mark work as complete.
